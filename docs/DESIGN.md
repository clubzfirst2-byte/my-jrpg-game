# 【レビュー依頼】ブラウザ向け2Dオープンワールド・アクションゲーム 設計書・実装計画（v0.1）

以下は、HTML / CSS / JavaScript で作るブラウザ向け2D見下ろし型オープンワールド・アクションアドベンチャー（iPhone対応）の設計書と開発計画です。
既存作品のキャラクター・名称・マップ・音楽・画像は一切使わず、完全オリジナルで制作します。

**次の観点で、問題点と改善案を具体的に挙げてください。**
1. 技術構成は妥当か（特に PixiJS と素の Canvas 2D のどちらがよいか）
2. iPhone Safari での性能・メモリ・操作性に懸念はあるか
3. 見下ろし視点での「高さ」の表現方法（標高レベル＋Z座標）に問題はないか
4. 環境シミュレーション（延焼・導電など）をスマートフォンで動く負荷に収められるか
5. ロードマップの順番や区切り（最初の試作品を P3 までとする）は適切か
6. 抜けている要素、または最初から入れるべきでない要素はあるか

---

## 0. コンセプト

- 2D見下ろし型のオープンワールド。広いフィールドを継ぎ目なく探索できる
- 高品質なドット絵
- 一本道ではなく、攻略の順番も方法も自由
- スマートフォン（特に iPhone）で快適に遊べる
- HTML / CSS / JavaScript が基本。描画は Canvas または WebGL
- 最初から全機能を作らず、遊べる小さな試作品から段階的に作る。段階ごとに動作テストを行う

## 1. 技術構成

| 領域 | 採用 | 理由 |
|---|---|---|
| 言語 | JavaScript（ES Modules）＋ JSDoc 型注釈（`// @ts-check`） | HTML/CSS/JS が基本という条件を守りつつ、型チェックで大規模化に備える |
| ビルド・開発サーバ | Vite | 速い。スマホから同じ LAN の PC につないで確認できる。本番ビルドも簡単 |
| 描画 | WebGL（PixiJS v8 を描画専用に使う） | iPhone でも大量のスプライト、パーティクル、ライティングを 60fps で描きやすい。ゲームのロジックはすべて自作し、描画部分は差し替えられるように切り離す |
| 物理 | 自作の軽量物理（円 / AABB の当たり判定＋高さ Z 軸） | 見下ろし視点で「高さ」を扱うため、汎用の物理エンジンは合わない |
| 環境シミュレーション | 自作のタイルグリッド型（10Hz、プレイヤー周辺だけ計算） | 延焼・導電・濡れ・温度を軽く処理できる |
| 重い処理の分離 | Web Worker | ワールド生成とチャンク生成をメインスレッドから外し、カクつきを防ぐ |
| 音 | Web Audio API | iOS のオーディオ制限（最初のタップで解禁）に対応。効果音は合成音から始める |
| セーブ | IndexedDB（使えない時は localStorage） | オートセーブとスロット管理 |
| 配布 | PWA ＋ GitHub Pages | iPhone でホーム画面に追加すると全画面で遊べる。テスト用の URL もすぐ用意できる |
| テスト | Vitest（ロジック）＋ Playwright（iPhone サイズでの E2E・スクリーンショット） | 段階ごとに自動テストする |
| CI | GitHub Actions | push 時にテストを実行し、Pages へ自動デプロイ |

### iPhone 向けの方針
- 内部解像度を固定（例：高さ 216px、横幅は画面比率に合わせる）し、整数倍に拡大してドットをくっきり保つ
- `100dvh` と safe-area-inset でノッチ・ホームバーに対応。ピンチズーム、スクロール、長押しメニューは無効化
- テクスチャアトラスは 1 枚 4096px 以下（iOS のメモリ制限対策）
- 横画面を推奨し、縦画面では回転を促す表示を出す

### ドット絵素材の方針
1. 初期段階では、統一パレット（32〜48 色）を使ってコードで生成したドット絵と仮素材で作る
2. 同時に Aseprite（JSON アトラス）を取り込める素材パイプラインを用意する
3. 後から本番素材（自作・外注・正規ライセンスのオリジナル素材）に差し替えるだけで済む構造にする

```
my-jrpg-game/
├─ index.html
├─ vite.config.js / package.json / manifest.webmanifest
├─ public/
│  ├─ assets/            # スプライト(atlas.png+json)、タイル、音、フォント
│  └─ icons/             # PWAアイコン
├─ src/
│  ├─ main.js            # 起動
│  ├─ core/              # ゲームループ(固定タイムステップ)、イベント、乱数(シード)、数学

│  ├─ world/             # チャンク管理、ワールド生成(Worker)、バイオーム、タイル定義
│  ├─ environment/       # 元素シミュ(炎/水/電気/氷/風)、昼夜、天候、四季
│  ├─ entities/          # プレイヤー、敵、NPC、オブジェクトの定義(データ駆動)
│  ├─ ai/                # 敵AI(状態機械)、NPCスケジュール
│  ├─ combat/            # ヒットボックス、ダメージ計算、状態異常
│  ├─ items/             # 武器・防具・素材・料理・強化
│  ├─ puzzle/            # 仕掛け(スイッチ、重さ、導電、光)、試練施設
│  ├─ quest/             # クエスト、会話、フラグ
│  ├─ ui/                # HUD、メニュー、マップ、インベントリ(DOM+CSS)
│  ├─ audio/             # BGM・効果音・環境音
│  ├─ save/              # IndexedDB、バージョン移行
│  └─ debug/             # FPS表示、当たり判定の可視化、ワープ、時間操作
├─ data/                 # JSON: アイテム、敵、レシピ、会話、配置物
├─ maps/                 # Tiled形式の手作りエリア(村、試練施設、ダンジョン)
├─ tools/                # 素材変換、パレット検証、ドット生成スクリプト
├─ tests/
│  ├─ unit/              # Vitest
│  └─ e2e/               # Playwright(iPhoneサイズ)
└─ docs/                 # 設計書、ロードマップ、テスト記録
```

### ワールドの作り方
- 大まかな配置（地方・バイオームの位置）は低解像度の「バイオーム地図」として手で設計する
- 細部の地形はシード固定のノイズで自動生成する（毎回同じ地形になる）
- 村・試練施設・ダンジョンなどの重要な場所は Tiled で手作りし、自動生成した地形にはめ込む
- 世界はチャンク（例：32×32 タイル）に分け、プレイヤー周辺だけ読み込む

## 3. ゲーム設計

### 3.1 世界観（完全オリジナル・仮名）
- **タイトル（仮）**：『星脈のワイルズ』
- **世界**：大地の下を流れる力の川「星脈（せいみゃく）」に支えられた大陸「アウラ」。古代の「灯（ともしび）の民」が残した遺跡が各地に眠っている
- **脅威**：星脈が淀んで生まれる黒い霧「澱（おり）」。土地を蝕み、魔物を生み出す
- **主人公**：記憶を失った旅人。古代装置「星環（せいかん）」に触れて目覚める
- **目的**：4 つの地方の「澱の核」を浄化し、大陸の中心にある「淀みの源」へ向かう。どの順番で攻略してもよく、最初から源に挑むことも可能

### 3.2 地方とバイオーム

| 地方 | バイオーム | 特徴 |
|---|---|---|
| はじまりの丘 | 草原・小さな森 | チュートリアル台地。ここで基本能力をすべて習得する |
| 囁きの森 | 深い森・沼 | 視界が悪い。延焼に注意。隠し場所が多い |
| 白嶺（はくれい）山脈 | 雪山・氷河 | 寒さ（防寒が必要）。雪崩、凍った湖 |
| 赤砂の海 | 砂漠・オアシス・遺跡 | 昼は暑く夜は寒い。砂嵐。地下遺跡 |
| 鏡湖と群島 | 湖・海・島 | 水泳、いかだ。雷雨のときの導電 |
| 地底 | 洞窟・鉱脈 | 暗闇（灯りが必要）。採掘 |

### 3.3 「高さ」の表現（2D 見下ろしの肝）
- タイルごとに標高レベル（0〜15）を持たせる。段差は崖として描く
- エンティティは Z 座標を持ち、スプライトを上にずらし、地面には影を描く。これでジャンプや滑空を表現する
- **登攀**：崖の面に向かって進むと登り始め、スタミナを消費する。雨で濡れると滑る
- **滑空**：高い場所から飛び降りて滑空。炎の上昇気流で高度を上げられ、風で流される
- **水泳**：スタミナを消費。尽きると溺れて岸に戻される

### 3.4 アクション
移動 / ダッシュ（スタミナ消費）/ ジャンプ / 登攀 / 滑空 / 水泳 / 近接攻撃（3 段コンボ・溜め）/ 弓（狙う・属性矢）/ 回避（ジャスト回避でスロー＋反撃）/ ガード（ジャストガードで弾き返す）/ 投げる / 持ち上げる

### 3.5 環境システム（元素ルール）
各タイルと物体に、素材（草・木・石・金属・水・氷・布）と、状態（温度・湿り気・帯電・燃料）を持たせる。

| 組み合わせ | 結果 |
|---|---|
| 炎＋草木 | 延焼する。風下へ広がりやすい。燃えた跡は灰になり、時間が経つと再生する |
| 炎の熱 | 上昇気流（滑空に使える）、氷が溶ける、寒さを防ぐ |
| 雨・水 | 炎が消える、登攀が滑る、電気が通る |
| 電気＋金属・水 | 導電して範囲ダメージ。仕掛けの動力にもなる |
| 冷気＋水 | 凍って足場になる |
| 風 | 草や木が揺れる、炎・矢・軽い物体・滑空に影響する |
| 雷雨 | 金属装備に落雷 |

計算は 10Hz、プレイヤー周辺のアクティブ範囲のみ。範囲外は状態を保存して停止する。

### 3.6 時間・天候・四季
- 1 日＝実時間 24 分。光の色の変化と光源で昼夜を表現。夜は強い敵が出る。NPC は時間ごとの行動予定で動く
- 天候：晴れ・雨・雷雨・雪・砂嵐・霧。地方と季節ごとに起きやすさが変わる
- 四季：1 季節＝ゲーム内 7 日。タイルの色と見た目が変わり（紅葉、積雪、凍る湖）、採れる素材や出る敵も変わる

### 3.7 戦闘と成長
- **敵**：基本 4 系統（獣・澱の魔物・古代機械・亜人の野盗）×地方ごとの変種。中ボスが徘徊し、核ボスは 4 体＋ラスボス
- **敵 AI**：状態機械（見張る→気づく→仲間を呼ぶ→攻撃→逃げる）。炎や地形を利用する敵もいる
- **装備**：武器（剣・槍・大剣・弓・杖）は耐久度を持ち、鍛冶屋で強化・修理できる。防具は 3 部位で、耐寒・耐暑・耐電・隠密などの効果がつく
- **料理**：素材の組み合わせで回復＋一時効果。レシピは発見制
- **成長**：試練の報酬「星の欠片」で HP かスタミナを上げる。スキルツリーは「狩人／剣士／探求者」の 3 系統

### 3.8 探索と謎解き
- **試練の洞（ためしのうろ）**：各地に点在する小さな謎解き施設（目標 30〜60 か所）。クリアするとファストトラベル地点になる
- **測量石**：高い所で使うと周辺の地図が描かれる。それ以外の場所は歩いた範囲だけ地図が埋まる
- **星環の能力**（序盤ですべて習得し、組み合わせで解く）
  1. **蔓結び**：地面から蔓を生やし、足場・橋・ロープにする（燃える）
  2. **念動**：軽い物体を引き寄せる・押し出す
  3. **灯火**：光の球を置く。暗い場所の照明や光で動く仕掛けに使う
  4. **共鳴**：結晶や鐘を鳴らして遠くの仕掛けを起動する。敵をひるませる
- **複数の解法**：仕掛けは「重さ・炎・電気・光・風」のどれでも動かせるように、入力の種類だけを判定する作りにする
- **ダンジョン**：大型施設が 4 つ（核の居場所）。施設全体が動く仕掛けになっている

### 3.9 スマートフォン操作 UI

```
┌────────────────────────────────────────────┐
│ ♥♥♥♥  ◯スタミナ                 [地図][≡]  │
│                                            │
│                                     [能力]  │
│  (仮想スティック)              [弓] [攻撃]   │
│   ◯ 左下の半分のどこを触っても出る   [回避][跳ぶ]│
└────────────────────────────────────────────┘
```

- スティックは触った位置に出る方式。ボタンの役割は状況で変わる（壁の前では「登る」、空中では「滑空」）
- 弓は長押しでスローモーションになり、ドラッグで狙う
- ボタン配置とサイズは変更可能。押した時に振動で反応（端末が対応していれば）

## 4. 開発ロードマップ

| 段階 | 内容 | 完了条件・テスト |
|---|---|---|
| P0 環境構築 | Vite、フォルダ、ESLint、Vitest、Playwright、CI、GitHub Pages への配布 | CI が通る。iPhone で URL を開き、空の画面が出る |

| P2 立体移動 | 標高、ジャンプ、登攀、滑空、水泳、スタミナ | 移動モデルの単体テスト。テスト用のマップで全動作を確認 |
| P3 戦闘の基礎 | 剣コンボ、回避、ガード、弓、敵 2 種、HP、死亡と復活 | ダメージ計算・無敵時間のテスト。プレイしての確認 |
| ★最初の試作品 | 「はじまりの丘」の小さな島で、探索と戦闘を一通り遊べる状態 | |
| P4 オープンワールド基盤 | チャンクの読み込み、Worker でのワールド生成（シード固定）、バイオーム、地図、セーブ・ロード | 同じシードで同じ地形になるテスト。チャンク境界で継ぎ目がない。メモリ上限を守る |
| P5 環境システム | 元素シミュ、昼夜、天候、風、ライティング | 延焼・導電・消火のルールテスト。周辺だけ計算する時の負荷を測定 |
| P6 アイテム | インベントリ、装備、耐久度、素材採取、料理、強化 | データの整合性チェック（JSON の形式検証） |
| P7 謎解き | 星環の 4 能力、仕掛けの部品、試練施設 3 つ、ダンジョンの雛形 | 各試練を 2 通り以上の方法で解けることを確認 |
| P8 住人 | NPC、村、会話、クエスト、商店、時間ごとの行動 | 会話・フラグ遷移のテスト |
| P9 世界の拡充 | 四季、全地方、ボス、試練の量産、隠し要素 | 通しプレイの確認。セーブの互換性テスト |
| P10 仕上げ | 素材の本番化、BGM・効果音、最適化、PWA、難易度調整、遊びやすさ（ボタン配置・文字サイズ） | 実機での長時間プレイ（発熱・電池消費）。読み込み時間の測定 |

**各段階で共通して行うこと**：単体テスト → iPhone サイズの E2E とスクリーンショット → 公開 URL に配布 → iPhone 実機で操作して意見を反映。
